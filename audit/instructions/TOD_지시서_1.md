# TOD 지시서 1 — 자료 기반 구축, 시각 변수 검증, 시계 준비, 개발 탐색 (프로젝트 TOD, 1단계)

- 대상: Cursor agent
- 선행 조건: 없음 (새 프로젝트). TOD = time of day.
- 산출 보고서: `reports/TOD_보고서_1.md` (템플릿은 §12)
- 이 지시서의 §1(절대 규칙)은 이후 모든 TOD 지시서에 적용된다.
- 순서: Part A(§4) → B(§5) → C(§6) → D(§7) → E(§8) → F(§9). Part마다 끝나면 커밋한다.

## 1. 절대 규칙 (TOD 전체에 적용)

### 1.1 사실성
- 모든 수치는 이 프로젝트에서 실행한 코드의 출력에서만 가져온다.
- 기억, 추정, 다른 논문의 수치로 빈칸을 채우지 않는다. 확인하지 못한 것은 "확인 못 함"으로 쓰고 이유를 적는다.
- 실패한 단계는 실패로 보고하고, 오류 로그의 핵심 부분을 붙인다.

### 1.2 원본 보존
- 내려받은 파일은 `data/raw/`(개발) 또는 `data/locked/`(잠금)에 받은 그대로 두고 고치지 않는다.
- 내려받은 모든 파일의 바이트 수와 SHA-256을 `config/raw_checksums.tsv`에 적는다.
- 가공한 결과는 `data/processed/`에 둔다.

### 1.3 잠금
- 잠금 자료: **GSE48113, GSE122725** (§3). 나중에 사전등록한 확인 검정에 쓴다.
- 잠금 자료의 발현 값은 읽지 않는다. 출력, 요약, 미리보기도 하지 않는다.
  - 금지 예: `head`, `cat`, `less`, `zcat | head`, `pandas.read_*`, GEOparse·GEOquery로 파일 전체 읽기, 편집기에서 열기.
  - 메타데이터는 series matrix에서 `!`로 시작하는 줄만 한 줄씩 읽는다. `!series_matrix_table_begin` 줄을 만나면 그 즉시 읽기를 멈춘다.
  - 잠금 자료의 보충 파일(supplementary)은 내려받지 않는다. 파일 이름과 크기 목록만 적는다.
- 플랫폼 주석(GPL)은 잠금 대상이 아니다.
- 잠금을 어겼거나 어겼을 가능성이 있으면 즉시 멈춘다. 무엇이 얼마나 노출됐는지 보고서 "판단이 필요한 사항"에 정확히 적는다.

### 1.4 출처 무결성
- 시계 계수, 유전자 목록, 참조 행렬은 배포된 패키지나 저자가 직렬화해 배포한 모델 파일에서만 읽는다. 논문 PDF나 보충표에서 손으로 옮기지 않는다.
- 읽은 파일마다 경로, 패키지 버전, SHA-256, 항목 수를 기록한다. 문서에 항목 수가 적혀 있으면 나란히 적는다.
- 둘이 다르면 그 시계는 다음 단계로 넘기지 않고 보고한다.

### 1.5 라이선스
- 재배포 조건이 불명확하거나 등록이 필요한 참조 자료(예: CIBERSORT LM22)는 내려받지 않는다.
- 쓰는 패키지와 자료의 라이선스를 기록한다. 비상업 전용 등 제한이 있으면 표시한다.
- 제3자 자료 파일을 저장소에 커밋하지 않는다.

### 1.6 보고 방식
- 보고서에는 수치와 사실만 쓴다. "의미 있다", "좋다", "시사한다" 같은 해석과 결론은 쓰지 않는다.
- 같은 분석을 여러 방식으로 돌렸다면 모두 보고한다. 결과를 보고 고르지 않는다.

### 1.7 판단
- 지시서에 없는 판단이 필요하면 가장 보수적인 선택(자료를 덜 열고, 분석을 덜 하는 쪽)을 한다. 그리고 보고서 "판단이 필요한 사항"에 적는다.

### 1.8 기록과 재현
- git 저장소를 쓰고 Part마다 커밋한다. 커밋 해시를 보고서에 적는다.
- 무작위 과정의 시드는 `20261015`.
- R과 Python의 패키지 버전을 `config/env_versions.txt`에 적는다.

### 1.9 자원
- CPU 제한 없음. 스레드 상한 환경변수(OMP_NUM_THREADS 등), 병렬 작업자 수 상한, taskset을 두지 않는다.
- 메모리 상한 48 GB. 무거운 단계(RNAAgeCalc, 부트스트랩)는 `/usr/bin/time -v`로 감싸 경과 시간과 최대 RSS를 기록한다.
- GPU는 쓰지 않는다. 프로젝트 폴더는 20 GB 이하로 유지한다.

## 5. Part B — 내려받기, 해시, 메타데이터

### 5.1 내려받기
- **네 자료 모두:** series matrix 파일 전부(`GSExxxxx_series_matrix.txt.gz`, 플랫폼이 둘 이상이면 모두)와 사용된 GPL 주석 파일.
- **개발 자료:** series matrix에 처리된 발현 값이 없으면 보충 파일을 내려받는다. 어떤 파일을 왜 받았는지 적는다.
- **잠금 자료:** series matrix와 GPL만 `data/locked/`에 받는다. 보충 파일은 이름과 크기 목록만 적는다 (§1.3).
- 모든 파일의 바이트와 SHA-256을 `config/raw_checksums.tsv`에 적는다.

### 5.2 메타데이터 표
자료마다 `data/processed/{GSE}_samples.tsv`를 만든다.

| 열 | 내용 |
|---|---|
| dataset, gsm | |
| subject_id | 참가자 식별자 (원 값과 정규화한 값을 따로 둔다) |
| condition_raw | 원 필드 값 그대로 |
| condition | `control` 또는 그 밖의 조건 이름 (§3 기준). 기준에 없으면 `other` |
| period | 측정 구간 (예: baseline, deprivation, recovery, D1, D4, period1, period2) |
| light_group | GSE122725만: bright / dim |
| sample_type | 백혈구, PBMC, 전혈 등 (원 문구 근거) |
| platform | GPL |
| channel_count | `!Sample_channel_count` |
| clock_time_h | 채혈 현지 시각, 0–24 소수 (예: 07:30 → 7.5) |
| elapsed_h | 그 참가자·구간의 첫 채혈부터 지난 시간 |
| hours_awake | 마지막 기상부터 지난 시간 (구할 수 있을 때만) |
| circadian_ref_h | 멜라토닌 위상(DLMO 등) 기준 시각이 제공되면 그 값 |
| age, sex | 제공될 때만 |
| batch_fields | 스캔 날짜, 혼성화 배치 등 제공되는 것 |
| time_source | `given`(직접 제공) / `derived`(규칙으로 계산) / `NA` |
| raw_characteristics | 모든 characteristics를 원문 그대로 이은 문자열 |

- `derived`인 열은 어느 원 필드에서 어떤 규칙으로 계산했는지 보고서 §4.1에 적는다.
- 채혈 일정을 원 논문(GEO에 연결된 PubMed) 방법 절에서 확인해 유도했다면, 근거 문장을 짧게 원문 그대로 인용한다.
- 시각을 구할 수 없으면 NA로 두고 추측하지 않는다.
- 자료마다 다음을 낸다.
  - 참가자 수, 조건·구간별 샘플 수
  - 참가자당 샘플 수 분포 (최소·중앙값·최대)
  - clock_time_h 범위, 연속 채혈 간격의 분포
- §3의 참고 샘플 수와 나란히 적는다. 다르면 원 필드를 근거로 차이를 설명한다.

## 6. Part C — 개발 자료 발현 처리와 QC (GSE39445, GSE56931)

### 6.1 값의 의미
- `!Sample_data_processing`, `!Sample_label`, 채널 수를 원문 그대로 보고서에 인용한다.
- 두 채널 자료이고 값이 비율(공통 참조 대비 등)이면 그렇게 표시한다. 그 자료에는 §8.1의 `official` 방식을 쓰지 않는다.

### 6.2 로그 판정 (GEO2R 규칙)
- 원래 값으로 판정한다. 자료 전체 값의 분위수 q0, q25, q99, q100을 구한다.
- `q99 > 100`이거나, `q100 − q0 > 50`이면서 `q25 > 0`이면 "선형", 아니면 "로그"로 본다.
- 선형이면 0 이하 값을 NA로 두고 log2를 취한다. NA 수를 보고한다.
- 판정과 분위수를 보고한다. 이 단계에서 추가 정규화는 하지 않는다.

### 6.3 프로브 → 유전자
- GPL 주석의 유전자 기호 열을 쓴다 (열 이름을 보고한다).
- 기호가 없거나 둘 이상(`///` 등)인 프로브는 뺀다.
- 한 유전자에 프로브가 여럿이면, 그 자료 전체 샘플에서 평균 log2 값이 가장 큰 프로브 하나를 쓴다. 같으면 프로브 ID 사전순으로 앞선 것을 쓴다.
- 프로브 수, 유전자 수, 뺀 프로브 수를 보고한다.
- 출력: `data/processed/{GSE}_expr_gene_log2.tsv.gz`, `data/processed/{GSE}_probe_map.tsv`

### 6.4 QC
- 샘플별 중앙값과 IQR을 낸다. 샘플 중앙값들의 중앙값에서 3 MAD 넘게 벗어난 샘플은 표시만 한다 (빼지 않는다).
- 분산 상위 1,000개 유전자로 PCA를 한다. PC1–PC5 각각에 대해 다음 변수가 설명하는 R²를 표로 낸다: subject_id, condition, period, 배치 필드, cos·sin(2π·clock_time_h/24).
- 커밋: "TOD Part C"

## 7. Part D — 시각 변수 검증 (양성 대조)

- **목적:** clock_time_h가 맞게 정리됐는지 일주기 핵심 유전자로 확인한다.
- **자료:** 개발 자료의 control 샘플. clock_time_h를 구하지 못한 자료는 Part D와 F를 하지 않고 보고한다.
- **유전자:** PER1, PER2, PER3, NR1D1, NR1D2, ARNTL, CRY1, CRY2, DBP, TEF (플랫폼에 없으면 "없음").
- **모형** (R lme4, 유전자마다):
  - `expr ~ cos(2*pi*t/24) + sin(2*pi*t/24) + (1 | subject_id)`, t = clock_time_h
  - 추정은 REML로 한다. 리듬 검정은 ML로 맞춘 모형과 cos·sin을 뺀 모형의 우도비 검정(자유도 2)으로 한다.
  - 진폭 A = √(β_cos² + β_sin²) (log2 단위)
  - 정점 시각 = (24/2π)·atan2(β_sin, β_cos)를 0–24로 맞춘 값
- **참고 기준:**
  - (a) PER1, PER3, NR1D1, NR1D2의 정점 시각이 04–12시 안에 있다.
  - (b) PER3와 ARNTL 정점 시각의 원형 거리(0–12시간)가 6시간 이상이다.
  - 둘 다 맞으면 "통과". 아니면 "점검 필요"로 표시하고, 그 자료는 Part F를 하지 않는다.
  - 기준에 맞추려고 clock_time_h를 바꾸지 않는다.
- 커밋: "TOD Part D"

## 8. Part E — 시계 준비

### 8.1 RNAAgeCalc
- Bioconductor `RNAAgeCalc`. 버전과 설치 폴더의 DESCRIPTION·데이터 파일 SHA-256을 기록한다.
- **설정:** `tissue = "blood"`, `stype = "all"`, `idtype = "SYMBOL"`. 서명은 세 가지다.
  - `RA_GTEx`: `signature = "GTExAge"`
  - `RA_Peters`: `signature = "Peters"`
  - `RA_default`: 서명을 지정하지 않을 때의 혈액 기본값 (무엇인지 보고)
- **소스 확인:** `predict_age` 등 패키지 소스를 읽고 다음을 보고한다.
  - 입력 변환 (로그 여부, +1 등)
  - 계수가 저장된 위치 (패키지 데이터 객체 이름)
  - 서명별 유전자 수와 절편
  - 누락 유전자 처리 방식 (`impute.knn`이 무엇을 기준으로 채우는지)
- **포함률:** 서명별로, 네 플랫폼(GPL 주석의 기호 기준) 각각에 있는 유전자 수와 비율. 잠금 자료도 GPL로만 계산한다.
- **값 계산 (개발 자료만, 두 방식):**
  - `official`: `predict_age()`를 그대로 쓴다. 입력은 2^log2 값(선형)을 `exprtype = "FPKM"`으로 넣는다. 자동 대체된 유전자 수와 비율을 보고한다. §6.1에서 비율 자료로 표시된 자료에는 쓰지 않는다.
  - `lin`: 패키지 데이터에서 읽은 계수로 선형 예측값을 직접 계산한다. 패키지 내부 변환이 log2(FPKM+1)이면 그 자리에 log2 마이크로어레이 값을 그대로 넣는다. 다른 변환이면 소스 확인 결과를 적고 log2 값을 그대로 쓴다. 없는 유전자는 빼고(대체 없음), 쓴 유전자 수를 보고한다.
- 출력: `results/stage1/clocks/{GSE}_rnaage.tsv` (gsm, 시계, 방식, 값)
- 예측값의 분포(평균, SD, 최소, 최대)를 보고한다. 수치만 적는다.

### 8.2 연구자 모듈 시계 (적용 가능성 점검)
- `config/paths.yaml`의 `module_clock_dir`가 비어 있으면 이 절을 건너뛰고 "연구자 자료 미제공"으로 보고한다. 다른 출처에서 대신 구하지 않는다.
- 경로가 있으면:
  - 파일 목록, 바이트, SHA-256을 적는다.
  - 저자가 직렬화해 배포한 시계 모델 파일인지 확인한다. 형식, 객체 구조, 시계 이름, 모듈별 유전자 수, 종, 필요한 유전자 ID 형식, 입력 정규화 방식을 보고한다. 보충표에서 만든 표라면 그렇게 적고 쓰지 않는다.
  - 사람 bulk 마이크로어레이에 그대로 쓸 수 있는지 판단 근거를 적는다 (종·오솔로그 변환 필요 여부, 단일세포 입력 전제 여부, 입력 척도).
  - 네 플랫폼 포함률을 모듈별로 낸다.
  - 시계 코드와 계수를 고치지 않고 쓸 수 있으면 개발 자료 값을 계산한다 (`MC_{모듈}`). 고쳐야만 쓸 수 있으면 계산하지 않고 무엇이 막는지 적는다.

### 8.3 세포 분해 참조 포함률 (다음 단계 준비)
- 라이선스가 공개된 R 패키지의 참조만 쓴다: MCPcounter 표지 유전자, EPIC 참조(BRef, TRef).
- 참조별 유전자 수, 네 플랫폼 포함 수와 비율, 패키지 라이선스(DESCRIPTION 기준)를 보고한다.
- 세포 비율 추정은 하지 않는다.

## 9. Part F — 개발 탐색: 시계 값의 하루 주기

- **지위:** 개발 탐색이다. 확인 검정이 아니다. 수치는 사전등록 설계(효과 크기, 검정력)의 참고로만 쓴다.
- **자료:** Part D를 통과한 개발 자료의 control 샘플.
- **결과 변수:** §8.1의 `RA_*` × {official, lin}, 그리고 §8.2에서 계산했다면 `MC_*`. 모두 보고한다.

### 9.1 주 모형
- `score ~ cos(2*pi*t/24) + sin(2*pi*t/24) + (1 | subject_id)`, t = clock_time_h (R lme4)
- 추정은 REML, 리듬 검정은 ML 우도비 검정(자유도 2).
- 진폭 A, 최고–최저 차이 2A (시계 단위, 년), 정점 시각 (§7과 같은 식).
- 2A를 다음 두 값으로 나눈 비율도 낸다.
  - 개인 간 SD: 참가자별 평균 점수의 SD
  - 주 모형의 잔차 SD
- 귀무 모형 `score ~ 1 + (1 | subject_id)`의 ICC.

### 9.2 구간
- 참가자 단위 부트스트랩 2,000회, 시드 20261015.
  - 참가자를 복원 추출하고, 뽑힌 참가자의 control 샘플을 모두 쓴다.
  - 같은 참가자가 여러 번 뽑히면 새 ID를 붙인다.
- 2A의 95% 구간은 백분위 방식.
- 정점 시각 구간: 부트스트랩 정점 시각들의 원형 평균을 구한다. 각 값과 원형 평균 사이 원형 거리의 95번째 백분위를 반폭으로 쓴다.
- 수렴하지 않은 반복 수를 보고한다.

### 9.3 민감도
- **S1:** GSE39445에 hours_awake 선형 항을 더한다. 구할 수 없으면 생략하고 그렇게 적는다.
- **S2:** cos·sin에 참가자 무작위 기울기를 더한다. 수렴 여부를 보고한다.
- **S3:** 참가자별 OLS 코사이너. 샘플이 5개 이상이고 clock_time_h 범위가 16시간 이상인 참가자만 쓴다. 참가자별 2A의 중앙값·IQR과 정점 시각의 Rayleigh 검정(`circular` 패키지) 결과를 낸다.

### 9.4 그림 (확인용)
- 자료 × 시계 × 방식마다: x = clock_time_h, y = score, 참가자별 선, 주 모형 적합 곡선.
