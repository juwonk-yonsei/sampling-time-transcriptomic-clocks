# TOD 지시서 15 — 공개 저장소 준비 (GitHub·Zenodo) (프로젝트 TOD, 15단계)

- 대상: Cursor agent
- 선행 조건: TOD 지시서 14와 14b 완료 (그림과 보충 자료 확정)
- 산출 보고서: `reports/TOD_보고서_15.md` (템플릿은 §7)
- TOD 지시서 1의 §1을 적용한다.
- **새 분석은 하지 않는다.** 이번 단계는 저장소를 공개할 수 있게 정리하는 일이다.
- **push, 태그, 릴리스는 하지 않는다.** 연구자가 보고서를 확인한 뒤 직접 한다.
- **git 기록을 바꾸지 않는다.** rebase, squash, `filter-repo`, `commit --amend`(이미 있는 커밋)를 쓰지 않는다. 분석 계획 동결과 잠금 해제의 시각(2026-10-16 16:46, 16:49 KST)이 커밋 기록으로만 증명되기 때문이다.
- 커밋: "TOD15 release prep"

---

## 1. 이유 (이해용)

- 원고의 데이터·코드 가용성 문장에 저장소 주소와 Zenodo DOI가 들어가야 한다.
- Zenodo의 GitHub 연동은 공개 저장소에서만 된다. GitHub 릴리스를 만들면 Zenodo가 그 시점의 저장소를 보관하고 DOI를 준다.
- 공개하면 안 되는 것이 섞여 있으면 안 된다.
  - tAge 모델 파일, 그리고 모듈 구성 유전자와 계수(라이선스상 재배포 금지)
  - 원 GEO 자료(공개 자료이므로 내려받는 스크립트로 대신한다)
  - 비밀번호, 토큰, 키
- GitHub는 100 MB가 넘는 파일을 받지 않는다. 그런 파일이 과거 커밋에 하나라도 있으면 push 자체가 막힌다.

---

## 2. 점검 (먼저 하고, 문제가 있으면 멈춘다)

1. **현재 파일 목록**: `git ls-files`의 모든 파일과 크기를 표로 낸다. 50 MB 넘는 파일과 100 MB 넘는 파일을 따로 적는다.
2. **기록 전체의 큰 파일**: `git rev-list --objects --all`로 과거 커밋까지 모든 blob의 크기를 본다. 100 MB 넘는 blob이 있으면 경로와 커밋을 적고 **멈춘다.**
3. **공개 금지 내용 검사** (현재 파일과 과거 기록 모두)
   - tAge 모델 파일: 보충 표 S5의 체크섬과 파일 이름으로 찾는다.
   - 모듈 구성 유전자나 계수가 들어간 파일: 유전자 ID 열과 모듈·가중치·계수 열이 함께 있는 표를 찾는다.
   - 비밀 정보: `.env`, 토큰, 키, 비밀번호 형태의 문자열(`git grep`과 기록 검색).
   - 원 GEO 자료 파일(series matrix, 수치 행렬, FASTQ 등).
   - 과거 기록에서 하나라도 나오면 경로와 커밋을 적고 **멈춘다.** 기록을 지우는 방법은 연구자와 정한다.
4. 1–3의 결과에 문제가 없을 때만 §3으로 간다.

## 3. .gitignore 정리

- 원 GEO 자료, tAge 모델 파일, 내려받은 캐시, 큰 중간 파일, 개인 설정(편집기, Cursor 설정, `.env`)을 무시 목록에 넣는다.
- 이미 추적 중인 파일을 이번에 빼야 하면 `git rm --cached`로 추적만 끊는다(파일은 지우지 않는다). 무엇을 뺐는지 보고서에 적는다.

## 4. 새로 만드는 파일

### 4.1 `README.md` (영어)

다음 순서로 쓴다.

1. 제목과 한 문단 요약. 논문 인용과 Zenodo DOI 자리(`[DOI]`)를 둔다.
2. 폴더 구조: 폴더마다 한 줄 설명.
3. **기록 대조표**: 아래 사건의 커밋 해시, 날짜와 시각(KST), 커밋 메시지를 `git log`에서 뽑아 표로 둔다.
   - 분석 계획 동결(manifest 커밋)
   - 잠금 해제 전 기록(16:46)
   - 잠금 해제(16:49)
   - 이탈 D1–D12를 기록한 커밋
   - 확인 분석 실행 5
   - 각 사후 분석 단계(지시서 8–14b)
4. 동결 manifest 검증 방법
   - `scripts/verify_manifest.py`(§4.5)를 실행하는 법을 쓴다.
   - 재배포하지 않는 파일(tAge 모델 파일 등)은 원 출처에서 내려받은 뒤 같은 스크립트로 해시를 확인할 수 있다고 쓴다.
5. 재현 방법
   - 환경: R 4.5.3과 패키지, Python 3.12.7과 패키지. 잠금 파일(`renv.lock`, `requirements.txt` 등)이 있으면 가리키고, 없으면 지금 환경에서 버전 목록을 만든다.
   - 자료 내려받기: GEO 번호 6개와 내려받는 스크립트.
   - tAge 모델 파일: Zenodo doi 10.5281/zenodo.22166800 version 2에서 받는다.
   - 실행 순서: 스크립트 번호 순서와 각 단계의 출력, 대략의 실행 시간.
6. 포함하지 않은 것: tAge 모델 파일, 모듈 구성 유전자와 계수, 원 GEO 자료. 각각의 이유를 한 줄로 적는다.
7. AI 사용: 원고 2.11의 문장을 그대로 쓰고, 지시서와 보고서가 `audit/`에 있다고 적는다.
8. 라이선스: 코드는 MIT, 결과 표·그림·문서는 CC BY 4.0. 제3자 자료는 각 원 라이선스를 따른다.

### 4.2 `LICENSE`

MIT 라이선스. 저작권자는 `[Authors]` 자리표시로 둔다.

### 4.3 `CITATION.cff`

- cff-version 1.2.0, `message`, `title`, `version: 1.0.0`, `license: MIT`, `keywords`(원고 키워드 6개)
- `authors`: 이름·소속·ORCID 자리표시
- `date-released`, `repository-code`: 자리표시

### 4.4 `.zenodo.json`

- `upload_type`: software
- `title`: 원고 제목
- `creators`: 이름·소속·ORCID 자리표시
- `description`: README 요약 문단
- `license`: MIT
- `keywords`: 원고 키워드 6개
- `related_identifiers`
  - tAge 모델: doi 10.5281/zenodo.22166800, relation `requires`
  - GEO 6개: relation `references`
  - 논문: 자리표시로 남긴다(게재 후 `isSupplementTo`로 넣는다)

### 4.5 `scripts/verify_manifest.py`

- 동결 manifest의 파일마다 SHA-256을 다시 계산해 기록값과 비교한다.
- 결과는 일치, 불일치, 파일 없음(재배포 안 함)의 세 가지로 출력한다.
- 분석 코드는 건드리지 않는다.

### 4.6 `audit/`

- 지시서 1–15와 보고서 1–14b를 모은다. 파일 이름은 바꾸지 않는다.
- `audit/INDEX.md`에 날짜, 파일, 한 줄 목적을 표로 둔다.
- 저장소에 없는 지시서나 보고서가 있으면 목록으로 적는다. 연구자가 넣는다.
