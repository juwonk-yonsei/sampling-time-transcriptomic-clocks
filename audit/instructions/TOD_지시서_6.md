## 3. Part C — 확인 분석 코드

### 3.1 구조
- `scripts/confirm/` 아래에 단계별 스크립트를 두고, 진입점 하나(`scripts/confirm/run_confirm.sh`)가 다음 순서로 실행한다.
  1. 동결 확인: manifest의 해시 대조
  2. 잠금 해제 확인 (§3.3)
  3. 전처리 L1, L2, L3 (문서 §4–§5)
  4. 관문 (문서 §6). 실패한 자료는 이후 검정을 하지 않고 "gate fail"로 기록
  5. H1: 가족 P와 S1 (문서 §7)
  6. H2
  7. H3
  8. H4
  9. H5
  10. 모듈 수준 S4
  11. 민감도 (문서 §8)
  12. 결과 표와 요약
- 출력은 `results/confirm/`에 둔다. 이번 단계에서는 리허설 출력만 `results/stage6/rehearsal/`에 둔다.
- 모든 무작위 과정의 시드는 20261015.

### 3.2 문서와 코드의 대응
- 문서 §4–§8의 항목마다 그것을 구현한 파일과 함수를 적은 표를 만든다: `prereg/implementation_map.tsv` (열: 문서 절, 항목, 파일, 함수).

### 3.3 잠금 장치
- 잠금 자료의 발현 파일을 여는 함수는 하나로 모은다: `load_locked_expression()`.
- 이 함수는 다음 두 조건이 모두 맞을 때만 파일을 연다.
  - `config/unlock_approved.txt`가 있고, 그 안의 해시가 동결 manifest의 SHA-256과 같다.
  - 환경변수 `TOD_UNLOCK`이 같은 해시다.
- 조건이 맞지 않으면 파일을 열기 전에 오류를 낸다.
- `config/unlock_approved.txt`는 이번 단계에서 만들지 않는다.
- L3 보충 파일은 아직 받지 않았다. 내려받는 함수만 작성하고, 실행은 지시서 7에서 한다.

### 3.4 L3 형식 분기
- L3 counts 파일의 열 구성은 잠금 해제 직후 첫 줄(열 이름)만 읽고 정한다.
- 코드에 두 분기를 미리 넣는다: 유전자 식별자 열이 있을 때 / 없을 때(GENCODE 38로 transcript → gene).
- 유전자 식별자가 Ensembl ID이든 기호이든 처리한다.

### 3.5 GENCODE 38 표
- GENCODE release 38 기본 GTF를 받아 transcript → gene 표(transcript_id, gene_id, gene_name)를 만든다. 파일과 SHA-256을 기록한다.

## 4. Part D — 리허설

리허설 결과는 해석하지 않는다. 코드가 문서대로 작동하는지만 본다.

### 4.1 점수 수준 시뮬레이션 (통계 리허설)
- **설계:** 잠금 자료 메타데이터의 참가자별 시각과 샘플 수를 그대로 쓴다.
  - L1 Day 1: 147샘플, 22명
  - L1 Day 1 + Day 4: H4용
  - L2 period 1: 70샘플, 11명, 기상 기준 시각
  - L2 period 1 + period 2: H4용
  - L3: 58쌍, 메타데이터의 나이·성별·오피오이드 군
- **시나리오:** 확인 코드의 함수를 그대로 써서 다음을 돌린다.

| 대상 | null | planted |
|---|---|---|
| H1 (L1, L2) | A = 0 | 주 시계마다 F1의 GSE113883 매개변수 (A, φ, σ_u, σ) |
| H1 (L3) | 평균 Δ = 0 | 평균 Δ = F4의 c, Δ의 SD = 개발 GSE113883 아침–저녁 차이의 SD |
| H3 | 나이 기울기 0 | 나이 기울기 = −0.25 × c (10년당) |
| H4 | 상호작용 0 | Day 4(또는 period 2)의 진폭을 절반으로 |
| H2 | 구성 효과 0 | 구성 변수 1개로 매개 비율 0.6을 심는다 (L1 설계) |
| H5 | — | 평균 Δ = c (보정됨), 평균 Δ = 0.5c (보정 안 됨) |

- **반복:** null 500회, planted 200회. 시나리오마다 시드를 20261015에서 고정된 방식으로 바꿔 쓴다 (방식을 적는다).
- **보고:**
  - null에서 p < 0.05인 비율과 95% 구간 (1종 오류)
  - planted에서 p < 0.05인 비율 (검정력)
  - 추정값의 평균 편향: 2A, 정점, p_med, 나이 기울기, mean(Δ) − c
- 시뮬레이션에서는 부트스트랩을 하지 않는다.

### 4.2 발현 수준 파이프라인 리허설
확인 코드 전체를 처음부터 끝까지(전처리 → 관문 → H1–H5 → S4 → 민감도) 실행한다.

| 리허설 | 자료 | 목적 |
|---|---|---|
| R1 | GSE39445를 L1 모양으로 바꾼 자료. control → "Day 1", sleep_restriction → "Day 4". 플랫폼이 L1과 같다 | L1 경로 |
| R2 | GPL24324 probeset ID로 만든 합성 행렬 (값은 정규 난수, 시드 고정). 샘플 메타데이터는 GSE122725 메타데이터 모양 그대로 | L2 경로 |
| R3 | GSE113883 TPM으로 만든 합성 transcript 수준 counts. 유전자마다 round(TPM × 2×10⁷ / 10⁶)을 GENCODE 38의 그 유전자 transcript 하나에 넣는다. 열 구성 두 가지(유전자 열 있음 / 없음)로 두 분기를 모두 실행. 메타데이터는 GSE295758 모양으로, GSE113883 11명의 08시·20시 샘플을 쌍으로 쓰고 나이·성별·오피오이드 군은 합성 | L3 경로 |

- 리허설마다 종료 코드, 경과 시간, 최대 RSS, 산출 파일 목록을 보고한다.
- R1의 관문 판정과 가족 P 검정 결과 표도 보고한다.

### 4.3 독립 검사
- R1의 가족 P 검정(모형 M의 LRT, 시계 3개)과 R3의 대응 t 검정을 Python으로 다시 계산한다 (`statsmodels` MixedLM의 ML LRT, `scipy.stats.ttest_rel`).
- 값별 차이를 보고한다. 기준: LRT 통계량 상대 차이 < 1e-2, t 통계량 절대 차이 < 1e-8.

### 4.4 잠금 장치 시험
- 조건 없이 `load_locked_expression()`을 L1, L2 파일로 부른다. 오류가 나고, 파일이 열리지 않았음을 확인한 방법(예: open 호출 감시)과 함께 보고한다.
