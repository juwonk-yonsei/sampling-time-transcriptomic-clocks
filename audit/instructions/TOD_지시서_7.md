## 3. Part C — 확인 실행

### 3.1 실행
- `scripts/confirm/run_confirm.sh`를 한 번 실행한다.
- `/usr/bin/time -v`로 감싸고, 표준 출력과 오류를 `logs/confirm_run1.log`에 저장한다.

### 3.2 형식 적응
- L3 형식 분기는 코드가 첫 줄(열 이름)로 정한다 (문서 §9). 정해진 분기와 열 이름 목록을 기록한다.

### 3.3 커밋
- 끝나면 `results/confirm/` 전체를 커밋한다: "TOD7 confirm output run1". 커밋 해시와 시각을 기록한다.

### 3.4 실행이 실패하면
- 오류를 일으킨 부분만 최소로 고친다. 분석 정의(모형, 검정, 기준, 표본, 시계)는 바꾸지 않는다.
- 고친 내용(diff), 이유, 영향받는 출력을 `prereg/deviations.tsv`에 적는다.
- 다시 실행하고 실행 번호를 올린다 (`confirm_run2.log` 등). 앞 실행의 출력과 로그는 지우지 않고 따로 둔다.
- 분석 정의를 바꿔야만 실행할 수 있으면 멈추고 보고한다.

### 3.5 실행 뒤
- 결과 수치를 본 뒤에는 코드를 바꾸거나 다시 실행하지 않는다.
- 결과에 영향을 주는 버그를 나중에 발견하면, 사전등록 결과 표에는 첫 성공 실행의 값을 그대로 두고 고친 값은 따로 보고한다. `prereg/deviations.tsv`에 적는다.

## 4. Part D — 보고

- 결과는 사전등록 문서의 순서대로 낸다: 관문 → 가족 P(Holm) → 재현 판정 → H1 보조 점검(위상, 부호) → S1 → H2 → H3 → H4 → H5 → S4 → 민감도.
- 표마다 n(참가자, 샘플), 추정값 [구간], p, 해당 가족의 Holm q, 판정을 둔다.
- **독립 검사:** 관문을 통과한 가족 P 검정을 Python으로 다시 계산해 값별 차이를 낸다 (지시서 6 §4.3과 같은 방식과 기준).
